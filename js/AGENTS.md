# js/: the player's runtime

Plain ES modules loaded by `player.html` (`<script type="module" src="js/app.js">`)
and run as they are in Chrome and Firefox. No build, no transpiling, no npm
packages; third-party code is only what `vendor/` holds. The root
`AGENTS.md` rules apply; this file is the map of the modules and how code is
written here.

## Splitting app.js

`app.js` is being split section by section into feature modules
(`recordingsui.js` was the first), with `uv run dev/splitsection.py
"<heading>" js/<module>.js "<header>"` (`--dry` first: it names what
crosses and refuses what cannot). A moved module imports `$` and `el`
from `./dom.js`, and the player's `state` and helpers from `./app.js`, and app.js imports the
module's entry points back: a cycle ES modules resolve, as long as nothing
in the module runs while the modules load. Rules for the next ones: move a
whole section (both `/* ---- */` and `/* ==== */` headings bound one, and
nothing in the module may use an `app.js` binding while the modules load —
build such objects from `dom.js` only); a variable the other side assigns cannot cross
(give it a function, as `newPlayRun()` for `playRun` and `startReset()` for
`resetting`, or move consecutive sections together so that the variable
stays on one side: `uv run dev/splitsection.py` takes one section, so the
headings in between were masked for the move and put back after it); check every import
form (`import * as store` too), run `node dev/namecheck.mjs` (it finds
exactly that kind of miss), then make sure the module loads at all (a duplicate export is a
SyntaxError that stops the whole player: every scenario then fails at "the
connection"), play a channel, a film and an episode
with the console open and run the scenarios of that feature. A
`ReferenceError` at runtime is the typical miss.

## How code is written here

- **Typed modules stay clean.** `config.js`, `library.js`, `api.js` and
  `playback.js` begin with `// @ts-check` and carry JSDoc types (the shared
  shapes are typedefs: `Config`, `Settings`, `ListItem` in `config.js`;
  `CatalogueItem`, `Category`, `Programme`, `RequestOptions`,
  `StreamOptions` in `api.js`; `Provider`, `Group` in `library.js`;
  `PlaySpec`, `LoadInfo` in `playback.js`). New code in them gets its
  JSDoc too, and `node dev/typecheck.mjs` must report nothing: it counts
  every error the checker finds there. A cast is written
  `/** @type {T} */ (expr)` with a comment saying why the declared type is
  wrong; no `any` where the shape is known. A module joins the list in
  `dev/typecheck.mjs` once it is clean. The other modules are not typed:
  `namecheck.mjs` covers them for names and imports only.
- **Extension APIs through `browser.js`** (`api.storage…`), never a bare
  `chrome.` in shared code: Firefox runs the same file.
- **Per-account lists only through `config.js`**: `updatePersonal` takes a
  browser lock so two open tabs do not undo each other's favourites and
  history. Keys are `<name>:<scheme>://<host>:<port>/<user>`. Do not write
  `storage.local` for lists directly.
- **Settings defaults** live in `config.js`; a new setting gets its default
  there, a control in `player.html` (Settings), wiring in `setupui.js`, strings in
  all languages, and a line in `docs/user-guide.md`.
- **Text through `t()`**; static markup through `data-i18n*` attributes.
- **Provider data is untrusted**: names, URLs, EPG text and metadata are
  shown as text (`textContent`, `el()`); markup is written only from icon
  constants (`dev/htmlcheck.mjs` enforces it, and `eval`/`new Function` are
  refused); credentials never appear in what is shown or logged (the
  `noleak` scenario looks), links are built only to
  known services (`titlelinks.js`), and a provider URL is never navigated to.
- **No new permissions** without a reason the stores will accept; the AMO
  reviewer notes (`firefox/reviewer-notes.txt`) must then explain it, and the
  store texts and privacy policy may need a line.
- **Performance**: lists can hold 55,000 items. Anything per row runs on scroll
  frames; cache Intl instances (`format.js`); fetch lazily (`library.js`).
- **Comments explain why** in full sentences, as the surrounding code does.
  Some older comments are in Finnish; write new ones in English.

## Testing a change here

Pure functions (parsers, name tidying, filters, formatters, sync merge) get
cases in `dev/unitcheck.mjs`. Anything that needs the page gets a scenario in
`dev/playcheck.mjs` against `dev/mock/server.mjs`; see `dev/AGENTS.md`.
Playback, storage and permission changes are run in Firefox as well.
