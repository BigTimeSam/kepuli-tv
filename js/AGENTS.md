# js/: the player's runtime

Plain ES modules loaded by `player.html` (`<script type="module" src="js/app.js">`)
and run as they are in Chrome and Firefox. No build, no transpiling, no npm
packages; third-party code is only what `vendor/` holds. The root
`AGENTS.md` rules apply; this file is the map of the modules and how code is
written here.

## The modules, by area

**The application**

| Module | Role |
| --- | --- |
| `app.js` (~7,000 lines) | state, every view, event wiring. One `state` object near the top; sections are marked `/* ---- name */` (the address, covers, info panel, programme guide, reminders, recordings, the next episode, accounts, sync, external player, the picks…). Find with `grep -n "^/\* -" js/app.js` and read the section you change |
| `rows.js`, `vlist.js`, `listnavigation.js` | list rows (built on every scroll frame: keep them light), the virtualised list, cursor and return positions by item |
| `picker.js`, `modal.js`, `rowmenu.js`, `poster.js` | shared UI parts: every drop-down, dialog closing, the row menu, covers with fallback. Reuse them |
| `playerlayout.js`, `theme.js`, `route.js` | narrow-window panes, colour theme, the address (`#/live/...`) and tab title |
| `channelchoices.js` | the Choose countries / Choose categories dialog (`CountryPicker.show({ onSave, texts })`) and hidden channels |
| `cataloguesearch.js`, `programmesearch.js`, `name.js` | catalogue search, guide search, name tidying and accent-folding search keys |
| `mediafilters.js`, `titleinfo.js`, `titlelinks.js`, `rating.js`, `format.js` | film/series filters and facts, details strip, IMDb/YouTube links (known services only), ratings, Intl formatters |

**Providers**: each answers the same questions (account, categories,
lists, series info, stream URL) for its kind:

| Module | Kind |
| --- | --- |
| `api.js`, `xtream.js` | Xtream Codes `player_api.php`, URL building |
| `m3u.js`, `m3usource.js`, `fetchtext.js` | M3U parsing, a playlist as a catalogue, streamed and gunzipped downloads |
| `stalker.js` | Stalker/Ministra portals (MAC in a cookie set by a `declarativeNetRequest` session rule) |
| `library.js` | the lazy data layer over them: load as little as possible, as late as possible |
| `permissions.js` | optional host permissions, asked for per provider host |

**Programme data**: `epg.js` (per channel, lazily), `guide.js` + `xmltv.js`
(an M3U's XMLTV), `epggrid.js` (the guide grid), `picks.js` (the start page's
"on your channels now and soon"), `international.js`, `logos.js` +
`logoindex.js` (generated by `dev/logos.mjs`: do not edit).

| --- | --- |

**Storage and settings**

| Module | Role |
| --- | --- |
| `config.js` | settings, accounts, and the per-account lists (favourites, recents, resume, reminders, channels, interests) |
| `channelprefs.js` | personal presentation: hidden, order, countries, `movieCategories`, `seriesCategories` |

## How code is written here

- **Extension APIs through `browser.js`** (`api.storage…`), never a bare
  `chrome.` in shared code: Firefox runs the same file.
- **Per-account lists only through `config.js`**: `updatePersonal` takes a
  browser lock so two open tabs do not undo each other's favourites and
  history. Keys are `<name>:<scheme>://<host>:<port>/<user>`. Do not write
  `storage.local` for lists directly.
- **Settings defaults** live in `config.js`; a new setting gets its default
  there, a control in `player.html` (Settings), wiring in `app.js`, strings in
  all languages, and a line in `docs/user-guide.md`.
- **Text through `t()`**; static markup through `data-i18n*` attributes.
- **Provider data is untrusted**: names, URLs, EPG text and metadata are
  escaped when shown (`textContent`, not `innerHTML`), links are built only to
  known services (`titlelinks.js`), and a provider URL is never navigated to.
- **No new permissions** without a reason the stores will accept; the AMO
  reviewer notes (`firefox/reviewer-notes.txt`) must then explain it, and the
  store texts and privacy policy may need a line.
- **Performance**: lists can hold 55,000 items. Anything per row runs on scroll
  frames; cache Intl instances (`format.js`); fetch lazily (`library.js`).
- **Comments explain why** in full sentences, as the surrounding code does.
  Some older comments are in Finnish; write new ones in English.

## Testing a change here

Pure functions (parsers, name tidying, filters, formatters, sync merge) get
cases in `dev/unitcheck.mjs`. Anything that needs the page gets a scenario in
`dev/playcheck.mjs` against `dev/mock/server.mjs`; see `dev/AGENTS.md`.
Playback, storage and permission changes are run in Firefox as well.
